独立的 S3 兼容存储为 `backup_target: s3` 实例和 HA 集群提供共享的 pgBackRest
仓库。支持三种存储类型，每种都有自己的示例分组。

## 激活一种存储类型

`hosts.ini.example` 声明了全部三个分组；`[s3]` 下同一时间只激活一个子组：

```ini
[silo_s3]
s3-01 ansible_host=192.0.2.20 private_ip=192.0.2.20 ansible_user=root ansible_port=22

[s3:children]
# minio_s3
silo_s3
# rustfs_s3
```

复制对应的示例变量文件：

```bash
cp group_vars/silo_s3/main.yml.example group_vars/silo_s3/main.yml
```

## `group_vars/<type>_s3/main.yml.example`

示例文件逐字段带注释；最常修改的字段：

| 变量 | 含义 |
|------|------|
| `pgcli_s3_type` | `minio`、`silo` 或 `rustfs`；必须与分组名一致 |
| `pgcli_s3_name` | 实例名（默认 `backup`） |
| `pgcli_s3_api_port`、`pgcli_s3_console_port` | S3 API 与 Web 控制台端口 |
| `pgcli_s3_listen` | 监听地址；TLS + 网络边界保护存储 |
| `pgcli_s3_tls` | 提供 HTTPS；pgBackRest 拒绝明文 HTTP |
| `pgcli_s3_root_user` | root/access 用户 |
| `pgcli_s3_root_password` | root 密钥；多机网格必须放在 `secrets.yaml` |
| `pgcli_s3_drives` | 每个盘一个目录；留空则使用 `pgcli_s3_data_dir` |
| `pgcli_s3_data_dir` | 单机数据目录 |
| `pgcli_s3_endpoints` | 显式覆盖自动派生的端点矩阵 |
| `pgcli_s3_tls_sans`、`pgcli_s3_cert_cn` | 额外 SAN / 证书 CN |
| `pgcli_s3_tls_cert`、`pgcli_s3_tls_key` | 自带证书对 |
| `pgcli_s3_force` | 重建容器 |
| `pgcli_s3_buckets` | 安装后要创建的 bucket |

## 布局由主机数与 drives 决定

| 主机数 | drives | 模式 | 每个节点的参数 |
|--------|--------|------|----------------|
| 1 | 0 | SNSD | `--data-dir` |
| 1 | N | SNMD | `--drive` × N |
| >1 | 0 | MNSD | `--data-dir` + 每节点一个 `--endpoint` |
| >1 | N | MNMD | `--drive` × N + 每节点每盘一个 `--endpoint` |

端点矩阵按 inventory 顺序、用每台主机的 `private_ip`（回退 `ansible_host`）
生成，因此每个节点拿到相同的列表。多机网格需要共享的 root 密码与共享证书；
单机存储自行生成 CA。`rustfs` 不支持 MNSD：多机时每个节点都必须配置 `--drive`。

## 部署

```bash
# 当前激活的存储类型分组
uv run ansible-playbook playbooks/deploy-s3.yaml

# 指定类型 / 部分节点 / 强制重建
uv run ansible-playbook playbooks/deploy-s3.yaml -e pgcli_s3_group=minio_s3
uv run ansible-playbook playbooks/deploy-s3.yaml -e pgcli_s3_nodes=db-01
uv run ansible-playbook playbooks/deploy-s3.yaml -e pgcli_s3_force=true
```

## 作为备份目标使用

在数据库模式分组（`crosshost`、`ha_cluster` 等）中指向某个存储节点：

```yaml
pgcli_backup_s3_host: s3-01
pgcli_backup_s3_port: 9000
pgcli_backup_s3_bucket: pgbackup
pgcli_backup_s3_access_key: admin
# secret 放在 secrets.yaml：pgcli_backup_s3_secret_key
```

然后在实例上设置 `backup_target: s3`（创建时固定），或按
[HA 集群](./ha/)页面的方式配置 HA 备份。`pg_instance` 角色会解析
`<private_ip>:<port>`、从 `<base>/tls/<type>/<name>/ca.crt` 复制存储 CA，并在
创建实例前执行 `pg backup setup`。

如果存储**不在**本 inventory 中，省略 `pgcli_backup_s3_host`，改设
`pgcli_backup_s3_endpoint: host:port`（不带 scheme），角色会退回
`pg backup fetch-ca`。

可选参数：`pgcli_backup_s3_region`、`_s3_path`、`_no_verify_tls`、`_ca_file`、
`_ca_sha256`（见各模式示例文件）。

## 移除

`deploy-s3.yaml` 只负责部署。销毁存储在对应节点上用产品 CLI 执行：

```bash
pg addon remove <type> --name <name> --clean-data
```
